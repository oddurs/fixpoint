# fixpoint

A 320×200 BMP that is also a boot sector and a zip. Booted, it redraws its own pixels
with rule 110. The project page is https://fixpoint.oddurs.com.

## Commands

- `scripts/setup` once per clone: hooks, a uv `.venv`, toolchain check.
- `scripts/task check` is the whole gate: lint, then rebuild everything and require the
  committed artifacts byte-identical, then `verify.py` (boots qemu), then the site.
- `scripts/task test` alone skips the site build; `make run` boots it in a qemu window.
- Site dev server: `cd site && npm run dev`.

## Traps

- `stub.asm` is generated by `build.py`. Edit `build.py`, never `stub.asm`.
- `fixpoint.bmp` embeds a zip of `main.asm`, `stub.asm` and `build.py`. Any edit to one of
  them changes the image, so rebuild and commit `fixpoint.bmp`, `stub.asm` and
  `docs/anatomy.svg` with it. CI fails if they differ from what the source builds.
- The file size is fixed at 88,555 bytes because it doubles as the boot jump (`EB 59`).
  The source zip must fit in the padding: about 1.1 KB of headroom is left, and
  `build.py` asserts it. Growing those three files past that changes the whole layout.
- Builds must stay deterministic: no timestamps, no randomness, pinned matplotlib and
  fonttools (the SVG is compared byte for byte).
- The site's text is `site/src/post.md`, written for readers arriving from a link. It is
  deliberately separate from `README.md`, which is for people in the repo. Keep their facts
  in agreement; never generate one from the other.
- The page ships no JavaScript (the footer says so). Figure 1's interactivity is CSS that
  `demo/figures.py` writes into the SVG.
- If you change the picture's pixels, the video is stale: `make demo` re-records it (needs gdb).

## Deploy

Merging to `main` deploys: `pages.yml` builds the site, publishes it to GitHub Pages and
fails unless the live page shows the new build. The domain is a Cloudflare CNAME
(`fixpoint` → `oddurs.github.io`, DNS only; proxying breaks the certificate).

## Workflow

- IMPORTANT: Never commit to `main`. It advances only through a merged pull request.
- One unit of work, one worktree, one branch, one PR: `scripts/agent start fix/the-thing`,
  then work in the printed path.
- Full loop, unattended: `scripts/agent commit "..."` → `scripts/agent pr --title ... --body ...`
  (sets squash auto-merge) → `scripts/agent done` (waits for CI and the merge, watches the
  deploy go live, removes the worktree and branch).
- `scripts/task check` must pass before a PR. The hooks enforce it; never `--no-verify`.
- Conventional Commits, subject ≤ 72 chars, imperative, no trailing period.
- PR body: the problem, the approach, and where a reviewer should be sceptical.
- No AI or assistant attribution in commits, PRs, comments, or docs.
